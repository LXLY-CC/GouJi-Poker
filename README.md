# 够级规则和玩法介绍

六个人、四副牌、两个联邦的够级玩法指南：牌面大小、够级牌门槛、开点 / 烧牌 / 让牌 / 够死级 / 闷牌、名次计分、进贡，以及枣庄、滕州一带的六副牌带鹰打法。页面带三个小工具：点座位看联邦与对头、选牌判定够级牌、选名次算联邦得分。内容为简体中文。

```sh
bun install --frozen-lockfile
bun run dev
MINI_APP_ID=平台应用ID MINI_APP_VERSION=1.0.0 bun run build
```

预览：`http://127.0.0.1:5194/`。只上传 `dist/package/app.zip`，不要上传项目目录或旁边的 `package.json`。

## 应用 ID

`manifest.json` 里的 `id` 目前是占位符 `01900000-0000-7000-8000-000000000000`（仅为满足打包校验的 UUIDv7 格式，除版本位外全为 0，不是真实的应用 ID），**必须替换**：在社区个人资料的应用页创建应用，复制应用页面分配的 ID，用构建命令传入即可，无需手动改文件：

```sh
MINI_APP_ID=应用页面分配的ID MINI_APP_VERSION=1.0.0 bun run build
```

构建脚本（`scripts/package.ts`）会把环境变量里的 ID 和版本号写入打包用的 manifest。版本号必须是 `x.x.x` 三段数字；新正式发布必须高于已发布的最高版本。

## 权限

只申请实际用到的四项：

- `user.read`：显示当前玩家身份。
- `theme.read`：跟随社区深浅主题与语言。
- `storage.read` / `storage.write`：记住上次看到的章节和三个小工具的状态；存储不可用时仍可正常阅读。

没有网络端点、没有远程素材、不访问父 DOM。包内不要放任何令牌或秘密。

## 调试与提审

调真实 SDK：`MINI_APP_ID=应用ID MINI_APP_VERSION=1.0.0 bun run build:debug` 后上传 sandbox，在 DevTools 选择微应用 iframe 看日志和断点。

沙箱构建固定保留 7 天，过期不可恢复；需要重新测试时改内容或版本号后重新打包。提审流程与材料清单见 [提审说明](../../docs/submission-review.md)，完整开发说明见 [开发说明](../../docs/developer-guide.md)。

## 规则口径说明

- 主线是青岛经典四副牌打法（216 张、每人 36 张）。
- 「鹰」没有全国统一的点数：指南里如实列出三种常见桌规（当大过王的「鹰王」/ 当大王打 / 洗牌前挑出不入局），并提醒开局前先约定，没有把其中一种冒充为正统。
- 六副牌带鹰一节另含买 3 与革命、枣庄不憋 3 房与滕州憋 3 房（开点发 4、憋贡）的区别。

规则在 `src/logic.ts`（够级牌判定、联邦计分、座位关系），平台适配在 `src/host.ts`，内容在 `src/template.html`；缺少权限或存储失败仍可阅读。保留 `../../sdk`，公共构建说明见 [示例目录](../README.md)。
